# «Сосны» — учебный Telegram-бот отеля

Python 3.12+, стандартная библиотека, SQLite, Telegram Bot API. Рабочий сценарий не использует ИИ.

## Возможности

- Календарь заезда и выезда, ручной ввод дат и подбор доступных периодов.
- Фотокарточки, сравнение и выбор категории номера.
- Завтрак, трансфер и фрукты с пересчётом суммы.
- Изменение дат, гостей и контактов без повторного заполнения всей анкеты.
- Подтверждение и отмена, защита от повторного создания брони.
- Ответы по базе знаний с сохранением шага анкеты.
- Уведомления менеджеру, передача диалога и ответы через Telegram.
- Тестовый режим гостя на аккаунте менеджера.

Отель и наличие номеров вымышленные, реальные платежи не принимаются. MeHotel и amoCRM не подключены. Фотографии — стоковые иллюстрации; [источники и авторы](hotel_bot/assets/rooms/SOURCES.md).

## Запуск без Telegram и ключей

```sh
python -m hotel_bot demo
python -m unittest discover -s tests
```

Сторонних Python-зависимостей нет. Демонстрация и автоматические тесты используют отдельные тестовые базы и не обращаются к Telegram.

## Запуск в Telegram

1. Создайте своего тестового бота через BotFather.
2. Скопируйте `.env.example` в `.env`.
3. Впишите токен в `TELEGRAM_BOT_TOKEN`. Ключ ИИ не требуется.
4. Запустите:

```sh
python -m hotel_bot telegram --hybrid-offline
```

Откройте бота в Telegram и нажмите «Запустить». Рабочая база создаётся в `data/hotel.db`. Остановка — Ctrl+C. Один токен должен обслуживаться одним процессом: не запускайте локальную копию с токеном уже работающего серверного бота.

На Windows также доступны `./run.ps1 demo`, `./run.ps1 test` и `./run.ps1 telegram --hybrid-offline`.

Для привязки менеджера выполните `python -m hotel_bot manager-link` и откройте полученную одноразовую ссылку со своего аккаунта. Ссылку не публикуйте. Для проверки гостевого сценария на том же аккаунте доступны `/guest_mode` и `/manager_mode`.

## Где менять проект

| Файл | Назначение |
|---|---|
| `hotel_bot/hotel.json` | Каталог учебного отеля, услуги и база знаний |
| `hotel_bot/assets/rooms/` | Фотографии и их источники |
| `hotel_bot/cards.py` | Тексты карточек и форматирование |
| `hotel_bot/calendar.py` | Календарь |
| `hotel_bot/engine.py` | Сценарий бронирования и кнопки |
| `hotel_bot/pms.py` | Учебные наличие и расчёты |
| `hotel_bot/telegram.py` | Telegram, доставка и обновление сообщений |
| `hotel_bot/storage.py` | SQLite и сохранение состояния |
| `tests/` | Автоматические тесты и отдельный ручной сценарий |

Каталог комнат первоначально записывается в SQLite. Изменение начальных цен и вместимости в JSON не перезаписывает уже существующие записи базы.

## Проверки и ограничения

123 автоматических теста охватывают сценарии бронирования, изменения параметров, отмены, календаря, контактов, карточек и менеджера. Учебные неоплаченные брони можно отменить после подтверждения гостя независимо от даты; возвраты и спорные случаи передаются менеджеру.

Модули ИИ оставлены для будущего этапа. В режиме `--hybrid-offline` клиент ИИ не создаётся и внешние вызовы ИИ не выполняются.

Токены, рабочая база, контакты гостей, логи и настройки доступа к действующему серверу в репозиторий не входят. Запуск ручных Telegram-проверок из `tests/manual_cards.py` требует собственного токена и явно включаемой отправки сообщений.
